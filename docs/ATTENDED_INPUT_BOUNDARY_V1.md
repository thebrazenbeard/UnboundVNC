## Input authorization design

The RFB host still discards KeyEvent (type 4) and PointerEvent (type 5) for ordinary/view-only sessions. After original per-session view approval, an OPTIONAL second local button explicitly opens and arms only a new synthetic test-owned WinForms form (the exact target HWND, owner PID, bounds, two-minute deadline). Under that distinct test lease, RfbInputDispatch handles bounded RFB KeyEvent/PointerEvent packets using trusted host observations and the lease. Accepted synthetic keys/pointers are queued into a bounded in-process queue and applied only to the test form on its own UI thread. No native keyboard/mouse input or Firefox access exists. The independently authenticated real controller peer, human qualification and actual OS effect route remain absent. TrustedControlObservation is a separate read-only Windows witness that captures foreground-root HWND, owner PID, exact rectangle, input-desktop name and UTC time using OS APIs; the only caller-supplied fields are the host-owned session epoch and current-session flag. The read-only observation is now wired only into the attended synthetic test-form RFB path, not into a native user input injector. Source code must not be interpreted as an installed or active runtime.

AttendedControlLease has NO DEFAULT CONTROL. ViewOnly cannot grant; only an explicit AllowControl transition for a bounded SYNTHETIC_TEST_OWNED_WINDOW target (HWND, process ID, exact rectangle), new session epoch and at most 5-minute expiry may grant one test lease. A Firefox window is intentionally refused. A real authenticated owner-selected Firefox window must have a separate, independently reviewed consent+target registration design rather than changing the synthetic discriminator.

Each proposed event is checked against trusted ON-HOST observed session epoch, current default desktop, session validity, foreground root window+owner PID, unchanged bounds, expiry, monotonic sequence, syntactically parsed bounded RFB payload and target rectangle. A pointer can use left button only; keys limited to printable ASCII. Enter, Tab, Escape, Backspace and shortcuts remain denied: neither generic control grant nor synthetic key sequences authorize sending a message, discarding a draft or switching target. Clipboard not forwarded.

Dispatcher callbacks must be synchronous, bounded, non-UI-blocking and exception-safe, and now enqueue only test-owned data. A separate bounded UI timer validates the current lease again before changing the test form, so a revoked or wrong-foreground queued event is discarded. The lease holds a lock across BOTH decision and callback delivery, so Stop/revoke cannot acknowledge completion while an admitted effect callback is still executing. This was a directly observed RED failure before the atomic change; positive, wrong-window, replay, lock, stale, expired and post-revoke tests are GREEN. The TryConsume methods without callbacks are ONLY policy probes, not evidence of an actual input effect.

Important model limits: most lease tests use synthetic host-observation fixtures; one test calls the real read-only Windows observation API and verifies fail-closed when the host says the session is not current. Production MUST bind this read-only witness to host-owned session epochs and independently authenticated control approval; no RFB-originated data or client claim may supply either. A Win32 observation alone is NOT operator authentication, is vulnerable to HWND reuse and focus races, and does not establish a trusted controller. Gate does not prove selected chat identity, tab, composer, draft or active generation. A host-minted sequence counts packets but does not defeat malicious repeated browser input: real exactly-once submission needs an authenticated replay-resistant per-action nonce/idempotency protocol above stock RFB. An OS input queue can outlive synchronous delivery; qualify revocation semantics against a real test-owned form before any real target is permitted. Synthetic tests cannot prove human consent.
