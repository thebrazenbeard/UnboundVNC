## Signing-free and zero-budget are not synonymous with trusted distribution

An unsigned NSIS/Squirrel executable can be built without purchasing signing services (tooling cost), but Microsoft documents SmartScreen unknown-publisher/hash reputation warnings; some Windows 11 Smart App Control settings may block unsigned executables. Self-signed certificates do not establish publisher reputation. [Microsoft SmartScreen guidance](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation). This is a **user-trust and distribution blocker**, not solved by a green CI build or by advising users to disable security settings. Do not publish unsigned binaries as a "safe installer" on the current evidence.

Original UnboundVNC material is source-available under the repository's free-personal-use/separate-commercial-rights license, **not OSI open source**. Public redistribution of modified original material and commercial rights require the owner's permission under that license. Electron, Chromium, Node, noVNC, Vite, NSIS compression modules and transitive dependencies retain their own notices/obligations. A bundled-file SBOM/license NOTICE review and explicit release authorization are still missing. Installer project source should not be conflated with distributable rights.

## What this Draft implements instead

The `Invoke-ViewerPreviewTransaction.ps1` CI-only `ApplyTest` now records phase and exact source file/directory hashes in a GUID-owned journal before and after the unsigned folder copy/rename. `Invoke-HostedCrashRecovery.ps1` starts the transaction as a **separate PowerShell process** on a GitHub-hosted Windows runner, force-terminates its **known PID** at each of two checkpoints, then uses a newly launched `RecoverTest` operation. Recovery will remove an incomplete **test-owned** sandbox only when the marker, **phase-to-physical-folder mapping** (`pending-verified` only at `.pending`, `app-moved` only at final app path), actual source inventory, journal inventory, staged app inventory and absence of unknown files/directories/junctions/receipts all agree. Swapped phase is a negative test. It refuses ambiguous or committed receipts and leaves state for manual investigation. Nothing touches the actual user's `%LOCALAPPDATA%`, registry, services, firewall, startup, or an actual VNC host.

**Limits:** Only after-copy and after-rename *process termination* are simulated, not arbitrary power loss, journal-update tear, concurrent adversarial mutation, receipt forgery, disk exhaustion, app-in-use upgrade, or signed installer rollback. A kill **between** folder rename and the journal update is ambiguous and deliberately refused. `Set-Content` plus `Move-Item` is **not fsync or a proven durable transaction**. Journal data is not cryptographically authenticated. No installer or binary artifact is uploaded; no real Windows user installation is performed.
